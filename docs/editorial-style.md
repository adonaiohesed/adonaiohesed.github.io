# 블로그 한국어 문체 기준

모든 한국어 서술문은 한다체로 쓴다. 기술 글, 안내 글, 개인 기록에 같은 기준을 적용한다.
차분하고 구체적으로 설명하되, 저자의 경험·감정·판단·가치관은 보존한다.

- 설명: `~한다`, `~이다`, `~된다`, `~있다`를 사용한다.
- 경험: 원래 시제를 유지해 `~했다`, `~였다`로 쓴다.
- 판단: `~라고 생각한다`, `~라고 판단했다`처럼 판단의 주체와 성격을 유지한다.
- 가능성: `~할 수 있다`, `~할 수도 있다`, `~일 가능성이 있다`의 차이를 유지한다.
- 권고·의무: `~권장한다`, `~필요하다`, `~반드시 해야 한다`를 서로 바꾸지 않는다.
- 부정: 동사는 `~하지 않는다`, 형용사는 `~하지 않다`로 문맥에 맞게 쓴다.
- 자기 지칭: 한국어 서술에서는 문맥에 맞게 `나`, `내가`, `나의`를 사용한다.
- 질문과 자기 다짐: 의문문과 `~하자`의 문장 기능을 유지한다.
- 목록·제목: 명사형이나 `~하기`가 적합하면 그대로 사용한다.
- 사람과 대상에 대한 존칭은 유지한다. `하셨습니다`는 `하셨다`로 쓸 수 있다.

실제 인용·대화·면접 답변·메일·프롬프트·코드 예문은 본문과 구분해 원문을 보존한다.
예문이 정중체라는 이유로 인용 목적에 맞는 말투를 바꾸지 않는다.

기존 글의 문체를 교정할 때는 영문, 코드와 주석, 인라인 코드, 수식, 제목과 앵커,
링크와 이미지, 수치와 조건, front matter와 공개 상태를 보존한다. 사실 갱신이나 설명의
추가·삭제·재구성은 별도 작업으로 다룬다. 새 글 작성과 AI 생성에도 이 기준을 적용한다.

교정 검증:

```sh
# 교정 전에 기준을 기록하고, 교정 후 같은 기준으로 비교한다.
bundle exec ruby tools/check_editorial_preservation.rb snapshot /tmp/tone-baseline.json _posts
# ...문체 교정...
bundle exec ruby tools/check_editorial_preservation.rb check /tmp/tone-baseline.json _posts
python3 -m unittest discover -s tests -v
bundle exec jekyll build
bundle exec ruby tools/check_site.rb _site
```

기준 파일은 각 교정 작업을 시작하기 전의 보호 구간을 기록한다. 새 예제나 섹션을 추가하는
정상적인 내용 변경과 문체 교정을 분리한다. 검사를 통과시키기 위해 교정 후의 상태로
기준 파일을 다시 만들지 않는다. 자동 보존 검사는 의미
보존의 일부만 검증하므로, 변경 문장의 문법과 의미 검토도 함께 수행한다.
