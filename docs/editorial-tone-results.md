# 한국어 한다체 교정 결과

## 적용 범위

- 현재 작업 트리의 `_posts` 240편을 모두 검토했다.
- 한국어 서술문이 교정된 글은 **159편**, 변경된 줄은 **4,513줄**이다.
- 나머지 **81편**은 이미 한다체이거나, 비어 있거나, 영문·코드·실제 예문으로 보존했다.
- 영문·코드·제목·원래 인용·수치·링크·메타데이터·공개 상태·줄 수를 보존했다.
- `_projects`·`_ctfs`의 포트폴리오 데이터와 사이트 UI 문구는 블로그 본문 교정 범위에 포함하지 않았다.
- [교정 전 목록](editorial-tone-inventory.csv)과 [글별 전후 해시·결과](editorial-tone-results.csv)를 보관한다.

## 편집과 검토

원문 작업 사본을 백업한 뒤 78편·83편·79편의 세 묶음으로 나누었다. 각 편집자는
10~15편 단위로 변경 줄과 문맥을 읽고, 활용·부정·시제·주체·가능성·권고 강도를 검토했다.
변환 초안의 형용사/동사 오판, 굵은 글씨 경계의 어미, 생략된 중첩 산문 등을 수동 보완했다.
통합 검토에서는 수동 보완 206줄과 복수 어절 변경 6곳, 전체 잔여 후보를 재확인했다.
추가 통합 검토는 본체가 순차 수행했으며, 별도 에이전트의 독립 교차 검토 완료로 보고하지 않는다.

다음 보호 조건을 전후 원문 비교로 검사했다.

- YAML front matter의 원문 일치.
- Kramdown GFM의 문서 구조, 제목, 코드 블록·인라인 코드·수식·raw 노드와 링크/이미지 속성·표시 문구 일치.
- 영문 단어·숫자 토큰의 순서, 한국어가 없는 줄의 원문 일치.
- 인용 문자열, 들여쓰기, 줄 수·개행 형식·구분선 일치.

자동 검사는 의미 보존의 일부를 검증한다. 문장 의미 전체를 수학적으로 증명하거나
기술적 사실을 새로 검증한 것으로 취급하지 않는다.

## 의도적으로 보존한 정중체

한다체 기준은 저자의 한국어 서술문에 적용했다. 아래는 기능을 보존하기 위한 예외다.

- General Behavior Questions의 STAR 면접 답변과 Amazon/Coupang의 면접 질문·답변 연습문.
- 협상 응답, 작별 이메일, 기도 인용, ARP 대화, 피싱 메시지, 화면 안내 문구와 프롬프트 예시.
- 기존 제목과 링크의 표시 문구, 코드 및 코드 주석, 수식.
- `claude_md_skill_md`의 중첩 펜스와 SQL Injection의 백틱 때문에 기존 Markdown 파서가
  코드로 해석하는 구간. 본문 재구성·펜스 수정은 하지 않았다.
- 명사형 목록과 자기 다짐의 `~하자`, 대상에 대한 주체 높임.

전체 잔여 후보를 문맥으로 분류했으며, 위 예외를 제외한 수정 대상 산문의 정중체 후보는 남지 않았다.

## 검증

- 전수 보호 비교: 240편 통과.
- `python3 -m unittest discover -s tests -v`: 13개 통과.
- 프로덕션 Jekyll 빌드: 통과.
- 검색·문체 표시 회귀 검사: 로컬 작업 사본 기준 250개 검색 목적지 통과.
- HTML-Proofer: 외부 요청을 제외한 321개 파일 검사 통과.
- 구문 검사와 diff 검사 통과. 기존 Markdown 줄바꿈을 위한 끝 공백은 보존했다.
- Chrome 390px·1280px에서 기술 글과 자기소개 글의 화면을 확인했다. 한국어 내용,
  EN/KR 전환, 코드 표시, 목차, 가로 넘침을 검증하고 스크린샷을 시각 검토했다.

디자인 일관성: 기존 글 레이아웃·타이포그래피·컴포넌트·제목·앵커를 유지했다.
실제 기기 검증과 외부 댓글·분석 서비스의 동작 검증은 수행하지 않았다.

## 유지 관리와 배포

`docs/editorial-style.md`, 프로젝트 `AGENTS.md`, 글쓰기 도움말과 두 글 생성기에
한다체 기준을 반영했다. 다음 교정에는 보호 비교 도구를 사용한다.

작업 중이던 글의 기존 수정·삭제·미추적 상태를 유지한다. 그중 교정이 필요했던
`milestone`의 본문 한 줄만 기존 HEAD 위에 따로 반영하여, 기존 메타데이터 수정이나
새 글·초안을 함께 커밋하지 않도록 분리한다.

배포 대상은 기존 GitHub Pages의 <https://adonaiohesed.github.io/>이다.
배포 결과와 운영 확인은 해당 커밋의
[Build and Deploy](https://github.com/adonaiohesed/adonaiohesed.github.io/actions/workflows/pages-deploy.yml)
및 최종 전달 보고를 따른다. 롤백 기준은 교정 전 커밋 `750ec58`이며,
필요할 때 이번 교정 커밋만 되돌려 같은 워크플로로 재배포한다.
